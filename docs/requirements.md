# listenosu 要件定義

osu!lazer のライブラリにある楽曲を、作業用 BGM として流し聴きするための非公式音楽プレーヤー。

## 1. 位置づけ

| 項目 | 内容 |
| --- | --- |
| 主用途 | 作業用 BGM・流し聴き（ライブラリ全体のシャッフル／連続再生、検索して選曲） |
| 配布 | 公開配布（GitHub Releases） |
| 対応 OS | Windows：一級 / macOS：二級 / Linux：努力目標 |
| ライセンス | MIT |
| 名称 | listenosu（公開前に osu! のブランド規約で名称の可否を確認する） |
| 表記 | README と About に「ppy 非公式」を明記する。osu! のロゴと Torus フォントは同梱しない |

## 2. 技術構成

- アプリ本体：Rust + egui（eframe）+ kira
- DB 読み取り：**C# ヘルパー（Realm .NET）を同梱**する
  - `realm_db_reader` は採用しない。対応するのが Realm フォーマット 9.9 のみで、lazer の client.realm（フォーマット 24）を読めないため（2026-10-17 調査）
  - ヘルパーはアプリの子プロセスとして常駐し、標準入出力の JSON Lines でやり取りする
  - lazer の DB は読み取り専用で開く。**書き込みは一切しない**
  - lazer と同時に起動して使える
  - lazer で譜面を追加・削除したら一覧に自動で反映する。Realm の変更通知が別プロセスの書き込みで届くかは試作で確認する。届かなければ client.realm の更新監視で代用する
- 音声ファイルの実体：`<lazer データ>/files/<hash[0]>/<hash[0..2]>/<hash>`

## 3. ライブラリ

### 3.1 データの取得
- lazer のデータフォルダは自動で検出する（OS ごとの既定の場所と storage.ini のカスタムパス）。見つからないときは初回起動時にフォルダを選んでもらう。設定画面から変更もできる
- 一覧から外すもの：lazer で非表示にした譜面（Hidden）、削除待ちの譜面（DeletePending）
- 全ルールセット（osu! / taiko / catch / mania）の譜面を対象にする

### 3.2 曲の単位
- **音声ファイルのハッシュ単位**で重複をまとめ、1 曲として扱う
- 同じ譜面セットでも難易度ごとに音源が違えば、別の曲として扱う
- 曲の代表メタデータは、その音声を使う譜面のうち先頭のものを使う

### 3.3 表示
- 曲名とアーティスト名は原語（Unicode）表示が既定で、ローマ字表示に切り替えられる
- 日本語を表示できるフォントを同梱する

### 3.4 検索と並べ替え
- 検索対象：曲名（ローマ字と原語）、アーティスト（ローマ字と原語）、ソース、タグ、譜面作者
- 空白で区切った語の AND 検索で、大文字小文字は区別しない
- 並べ替え：曲名、アーティスト、追加日、長さ、BPM、最終プレイ日

### 3.5 プレイリスト
- lazer のコレクションを読み取り専用のプレイリストとして表示する。編集は lazer 側で行う
- アプリ独自のプレイリストを作成・編集・削除できる
  - 曲は「音声ハッシュ＋曲情報の控え（曲名・アーティスト）」で保存する
  - ライブラリから消えた曲は「見つからない曲」として控えを表示し、再生時は飛ばす。lazer に再インポートされれば元に戻る

## 4. 再生

| 機能 | 仕様 |
| --- | --- |
| 基本操作 | 再生 / 一時停止 / 前の曲 / 次の曲 / シーク / 音量 |
| シャッフル | ON / OFF |
| リピート | なし / 全曲 / 1 曲 |
| 再生キュー | 「次に再生」「キューに追加」、並べ替え、削除 |
| クロスフェード | 0〜10 秒で設定でき、既定は OFF。自動の曲送りでは設定した秒数だけ重ね、手動スキップでは短いフェードにする |
| 開始位置 | 常に曲の頭から |
| 対応フォーマット | kira（symphonia）で読めるもの。少なくとも mp3 / ogg / wav / flac |
| 再生できない曲 | 音声ファイルが無い、またはデコードに失敗した曲は飛ばして次の曲へ進む |

### 4.1 状態の復元
- 終了時の曲、再生位置、キュー、音量、シャッフル、リピートを保存する
- 次の起動時は一時停止の状態で復元し、自動では再生しない

## 5. UI

### 5.1 メイン画面（lazer の選曲画面風）
- 再生中の曲の背景画像を、ウィンドウ全体にぼかして暗く敷く
- 曲一覧は右側に置くカード型リスト
- 曲情報（曲名、アーティスト、BPM、長さなど）は左上
- 再生操作は下部のバー
- 検索欄と、表示対象（全曲 / コレクション / プレイリスト）の切り替えは上部
- 背景画像は再生中の曲の分だけ表示し、一覧にはサムネイルを出さない
- 再生バーの上にオーディオスペクトラムを表示する（5.3）

### 5.2 ミニプレイヤー
- 同じウィンドウを小さくして切り替える（背景画像、曲名、シークバー、操作ボタン、細いスペクトラムだけを表示）
- ボタンまたはホットキーで切り替える
- 常に最前面にするかを ON / OFF できる
- 位置とサイズを記憶する

### 5.3 オーディオスペクトラム
- メイン画面では、再生バーのすぐ上、ぼかした背景の上に半透明のバー型スペクトラムを横一列に並べる
- ミニプレイヤーでは、シークバーの後ろなどに細いバー型で表示する
- 既定は ON。設定で変えられるのは ON / OFF だけ
- 色、本数、減衰の速さ、高さはテーマ定義に入れる。将来はテーマファイルで変えられる
- ウィンドウが隠れている間（トレイに常駐しているときなど）や一時停止中は、計算を止める
- 実現方式：kira の出力にカスタムエフェクトを挟んでサンプルを取り出し、FFT で周波数に変換する（Phase 2 で検証する）

### 5.4 テーマ
- 色、角丸、余白、フォントサイズ、背景のぼかしと暗さを**テーマ定義**にまとめ、UI はテーマ定義だけを参照する。色や寸法の値を UI のコードに直接書かない
- v1 は内蔵の lazer 風テーマ 1 つだけ。テーマ定義は、後からファイルで読み込めるようにシリアライズ可能な形にしておく
- テーマファイルの読み込みは v2 で行う
- 雰囲気は lazer に寄せる：濃い紫紺系の背景、ピンクのアクセント、角丸、滑らかなアニメーション。フォントは自由に再配布できるもの（例：Nunito + Noto Sans JP）を使う

### 5.5 言語
- 英語と日本語に対応し、OS の言語で自動選択する。設定で変更もできる
- 文言は翻訳ファイルで管理し、言語を後から追加できるようにする

## 6. OS 連携

| 機能 | 既定 | 仕様 |
| --- | --- | --- |
| メディアキー / OS のメディア表示 | ON | Windows SMTC、macOS Now Playing、Linux MPRIS。曲名、アーティスト、背景画像を渡す |
| システムトレイ | ON | × ボタンでトレイに入り、再生を続ける。終了はトレイのメニューから。初回だけ通知で知らせる。設定で「× で終了」に変えられる |
| Discord Rich Presence | OFF | 曲名、アーティスト、経過時間を表示する |
| グローバルホットキー | OFF | 既定ではキーを割り当てない。ユーザーが割り当てる |

## 7. 障害時の挙動

- lazer の更新で DB を読めなくなったら、最後に読めた曲一覧のキャッシュで再生を続け、「対応版への更新が必要」と警告して更新の確認へ誘導する
- ヘルパーが異常終了したら再起動を試みる。それでも失敗したら上と同じ扱いにする

## 8. 保存データ

- 設定、独自プレイリスト、再生状態、曲一覧のキャッシュは、OS 標準の設定フォルダとキャッシュフォルダに保存する
- lazer のデータフォルダには何も書き込まない

## 9. 配布と更新

- GitHub Releases で配布する。Windows は zip（ポータブル）、macOS は .app を入れた dmg
- 起動時に新しい版を確認し、通知だけする。自動アップデートはしない。確認は設定で OFF にできる

## 10. v2 以降の候補

- テーマファイルの読み込み、アプリ内のテーマエディタ
- lazer と同じ書式のフィルタ構文（`bpm>180` など）
- 曲ごとの音量正規化、再生速度の変更
- 一覧のサムネイル表示
