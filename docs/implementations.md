# listenosu 実装計画

要件は [requirements.md](requirements.md) を参照。

## 進め方

1. **UI 設計を先に固める**。DB と音声に依存しない `gallery` バイナリで、モックデータを使って全画面と全部品を表示し、見た目とテーマ定義を確定させる
2. 技術的に不確かな点（ヘルパー、クロスフェード）を試作で潰す
3. 本実装では、gallery で作った UI 部品をそのまま本体に組み込む

## 進捗の記録方法

- 各タスクはチェックボックスで管理する。着手したら `[~]`、完了したら `[x]` にする
- フェーズの完了条件を満たしたら、下の「進捗サマリ」の状態と完了日を更新する
- 決定事項や仕様変更は、末尾の「変更履歴」に日付付きで追記する

## 構成（予定）

```
listenosu/
├─ Cargo.toml              # workspace
├─ crates/
│  ├─ listenosu/           # 本体バイナリ（eframe アプリ）
│  ├─ ui/                  # テーマ定義・UI 部品・画面（gallery と本体で共有）
│  ├─ gallery/             # UI ギャラリー（モックデータで全画面と部品を表示）
│  ├─ library/             # 曲モデル・検索・並べ替え・ヘルパーとの通信・キャッシュ
│  ├─ player/              # kira による再生・キュー・クロスフェード
│  └─ platform/            # SMTC/MPRIS・トレイ・ホットキー・Discord
├─ helper/                 # C# (Realm .NET) ヘルパー
├─ assets/                 # フォント・アイコン・翻訳ファイル
└─ docs/
```

## Phase 2: 技術検証（試作）

- [ ] **ヘルパー**: Realm .NET で、起動中の lazer の client.realm を読み取り専用で開けるか
- [ ] **ヘルパー**: lazer で譜面を追加・削除したとき、変更通知が別プロセスに届くか（Windows / macOS）
- [ ] **ヘルパー**: 配布サイズを測る（self-contained + trim、可能なら NativeAOT）
- [ ] **ヘルパー**: lazer が使っている Realm のバージョンと、ヘルパーで採用するバージョンを揃える
- [ ] **kira**: 2 曲の音量 Tween によるクロスフェード、ストリーミング再生中のシーク、再生位置の取得
- [ ] **kira**: 曲の終わりを検知して次の曲を予約するときの隙間を測る
- [ ] **スペクトラム**: kira のカスタムエフェクトで出力サンプルをリングバッファに取り出し、FFT（realfft など）で周波数に変換できるか。クロスフェード中は 2 曲を混ぜた後の音を取れるか。CPU 負荷も測る

**完了条件**: 検証結果と採用方針を下の「変更履歴」に記録する。通知が届かない場合の代替（client.realm の更新監視）も決める

## Phase 3: ライブラリ読み取り（C# ヘルパー）
